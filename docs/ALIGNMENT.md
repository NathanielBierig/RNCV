# What we're building: owner's answers (2026-10-25)

Collected in short question batches so the project matches what the owner wants. Newest batches go at the bottom.

## Batch 1
- **Purpose:** mainly a **portfolio / job showcase**, so rigor and clear documentation matter most.
- **The number on screen:** **both**: a **finish chance** for the attacker (≈100% at the tap) and a separate **danger/health gauge** for the defender.
- **Where judgement comes from early on:** **the owner's BJJ knowledge + data**. The owner sets starting numbers per factor, and the labels adjust them.
- **Automation for the next version:** the overlay must **at least detect the attempt by itself**; factors may still come from labels.

## Batch 2
- **Showcase deliverables:** **demo video**, **clean GitHub repo**, **interactive app** (drop a clip in, see the overlay). No long written report needed.
- **Labeling pace:** aiming for **~60 attempts by the end of the week**; 150 may not be reachable (clip availability). Build models that train on what exists, with honest uncertainty.
- **Science vs. predictor:** **keep both, separate**. The pre-registered study stays frozen; the live predictor is its own model that can use priors and change freely.

## Rejected so far
- MVP 0.1 finish-% math (time ramp): a locked figure-four read ~2%, a knockout ~30%. Redesign in progress: `docs/MODEL_SPEC.md`.
