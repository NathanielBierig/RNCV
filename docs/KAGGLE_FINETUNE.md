# Fine-tune the pose model on Kaggle (step by step)

**What this does:** it teaches the pose model to find both fighters when they are tangled on the ground. It fine-tunes
**YOLO11m-pose** (17 COCO keypoints per person) on grappling and MMA images from two public datasets, then gives you one
`.onnx` file that runs on the laptop CPU. **No UFC footage goes to Kaggle.** The notebook only downloads the public datasets.

- Notebook: `notebooks/kaggle_finetune_pose/finetune.ipynb` (generated by `build_notebook.py` in the same folder; edit that file, not the notebook).
- Laptop wrapper: `notebooks/kaggle_finetune_pose/yolo_pose_onnx.py` (the notebook also writes a copy to its output).
- Local check: `smoke_test.py` runs every cell on CPU with ~60 images (it passed, see the end of this file).

## Why YOLO11-pose and not MMPose (RTMO / RTMPose)

1. **Least friction on Kaggle:** `pip install ultralytics` is enough. MMPose needs a compiled `mmcv`, which has no prebuilt wheels for Kaggle's current PyTorch, so it often fails or needs a 30-60 min source build.
2. **It fixes the right problem:** like RTMO, it is a one-stage model (finds people and joints in one pass), so fine-tuning raises its confidence on the half-hidden second fighter. A top-down RTMPose only refines boxes that another detector already found.
3. **One-line ONNX export.** It drops into `onnxruntime` on the laptop through a 70-line wrapper, with no torch needed. Cost: Ultralytics is **AGPL-3.0**, which is fine for this research project (see Licenses).

## The data subset (default CONFIG)

| Split | Source | Sequences | Images (estimate*) |
|---|---|---|---|
| train | Harmony4D grappling (`train/02_grappling`, `train/03_grappling2`), every 5th frame, 6 of 20 cameras | 49 | 12,900 |
| train | Harmony4D MMA (`train/12_mma` … `train/15_mma4`), every 10th frame, 6 cameras | 49 | 7,584 |
| train | VICOS BJJ sequences 0, 1, 2, 4, every 15th frame | 4 | 6,052 → ~3,800 kept** |
| val | Harmony4D `024_grappling`, `008_grappling2`, `007_mma3`, plus VICOS sequence 3 | 4 | 264 + 271 |
| test | Harmony4D official test sequences (`test/03_grappling2`, `test/15_mma4`, `test/16_mma5`), plus VICOS sequence 5 | 27 | 918 + 444 |

**Total: 28,433 images from 133 sequences.** *Counts come from the notebook's own planning step (`smoke_test.py --plan`), run locally on the real file lists. The final count is lower because frames with a missing person are skipped.

**In 37% of VICOS frames one athlete has no keypoints, mostly in back control and turtle. Those frames are skipped, because keeping them would teach the model to ignore the hidden athlete. Harmony4D covers those tangled cases instead.

- **Split by sequence, never by frame:** a whole recorded sequence (all its cameras) is in exactly one split. The notebook stops if a sequence lands in two splits.
- **Small download:** the zips total 352 GB, so the notebook never downloads them. It reads each zip's table of contents, then fetches only the sampled images and label files with HTTP range requests. That is about **4.1 GB of transfer and ~3.4 GB on disk** (an estimate; images are resized to 1024 px).
- Harmony4D frames are 4K. Each image is cropped around both people with random extra space (1.2-2.5x), so people appear at broadcast-like sizes.
- Harmony4D labels are 3D-fitted body models projected to each camera, so hidden joints still have positions. That is good for occlusion. Caveat: its hip points sit slightly higher and more inward than COCO hips.
- VICOS labels came from the dataset authors' detector (checked by them). They are useful, but they are not perfect ground truth.
- Bystanders in Harmony4D images are not labeled, so the model learns to ignore them. That is probably good for crowds. It does **not** solve the referee.

## Expected runtime (estimates)

| Step | Time on Kaggle T4 (estimate) |
|---|---|
| Install + list the zips | 5-10 min |
| Fetch + convert ~28k images | 30-60 min (depends on Hugging Face / VICOS server speed; locally 8 images/s with 8 threads) |
| Training | `TRAIN_HOURS` = **4 h** (a hard limit; roughly 20-30 passes over ~24k training images) |
| Evaluation (4 models on the test images) + ONNX export | 15-30 min |
| **Total** | **about 5-6 h**, i.e. 5-6 of your 30 weekly GPU hours. Kaggle's limit is 12 h per run |

## Click-by-click (one-time account setup first)

**0. Account (once):** kaggle.com → sign in → your profile picture → **Settings** → **Phone verification** → verify. Without it, Internet and GPU stay off.

1. **Get the file:** from the repo, take `notebooks/kaggle_finetune_pose/finetune.ipynb`.
2. **Create the notebook:** on kaggle.com, left menu **Create** → **New Notebook**.
3. **Import it:** in the notebook editor, menu **File** → **Import Notebook** → **Browse files** → choose `finetune.ipynb` → **Import**. (This replaces the empty starter cell.)
4. **Turn on GPU and Internet:** open the right sidebar (the **<** arrow at the top right if it's hidden) → **Session options**:
   - **Accelerator** → **GPU T4 x1** → confirm.
   - **Internet** → **On**.
   - Leave **Persistence** at "No persistence".
5. (Optional) In the first code cell (CONFIG) change `TRAIN_HOURS` (default 4.0) or `USE_VICOS` (see Licenses). Nothing else needs editing.
6. **Run it in the background:** top right **Save Version** → choose **Save & Run All (Commit)** → **Save**. You can now close the browser. The run keeps going for up to 12 h.
   - (Alternative: **Run All** in the editor. Then the browser tab must stay open, and Kaggle stops idle sessions.)
7. **Watch progress (optional):** kaggle.com → **Your Work** → the notebook → **Versions** → the running version → **Logs**.
8. **When it finishes** (status "Successful"): open that version → **Output** tab. Download these files:
   - `rncv_pose_v1.onnx` (~80 MB): the model.
   - `yolo_pose_onnx.py`: the laptop wrapper (identical to the one in the repo).
   - `rncv_pose_v1_results.md` + `rncv_pose_v1_metrics.json`: the scores. Send these to Claude.
   - (`runs/rncv_pose_v1/weights/best.pt`, only if you want to train further later.)
9. **Put the model in the repo folder:** move `rncv_pose_v1.onnx` into `C:\Users\netan\projects\RNCV\models\` (create the folder if needed). `models/` and `*.onnx` are git-ignored, so the model never goes into git.

If a run fails: open its **Logs**, scroll to the first red error, and paste it to Claude. Re-running is safe, because every cell skips work it already finished (within the same session).

## Plug the ONNX into `src/pose_smoke.py` (laptop)

1. Copy `notebooks/kaggle_finetune_pose/yolo_pose_onnx.py` to `src/yolo_pose_onnx.py`. It needs only numpy, opencv and onnxruntime, which the `ufc-cv` venv already has.
2. In `src/pose_smoke.py` `main()`, add a `--model` option and replace the two RTMO lines:

```python
    ap.add_argument("--model", default="rtmo", help="'rtmo' or a YOLO-pose .onnx path, e.g. models/rncv_pose_v1.onnx")
    ...
    if args.model == "rtmo":
        from rtmlib import RTMO
        model = RTMO(onnx_model=RTMO_M, model_input_size=(640, 640), backend="onnxruntime", device="cpu")
    else:
        from yolo_pose_onnx import YoloPoseOnnx
        model = YoloPoseOnnx(args.model)   # same call: model(frame, nms_thr=..., score_thr=...) -> (kps [N,17,2], scores [N,17])
```

3. Run it on the same clips and compare with the RTMO report (`reports/pose_smoke.md`):

```bash
C:/Users/netan/.venvs/ufc-cv/Scripts/python.exe src/pose_smoke.py --model models/rncv_pose_v1.onnx --score-thr 0.25 --nms-thr 0.65
```

Use `--score-thr 0.25` (the YOLO default person-score cutoff; RTMO's 0.3 means something different). The two-fighter selection,
tracking and referee filter work unchanged because the output format is the same. Expect yolo11m-pose to be about as slow as
RTMO-m on the CPU (an estimate). If it is too slow, set `BASE_MODEL = "yolo11s-pose.pt"` and train again.

**What counts as success:** two-fighter upper-body coverage at or above the 60% gate on the UFC clips (FINDINGS.md §4), compared
with RTMO's 26-59%. The Kaggle test numbers (Harmony4D/VICOS) are only a proxy, because UFC broadcast footage looks different.

## Local check (done, no GPU)

`smoke_test.py` ran every notebook cell on the laptop CPU (`yolo` venv, ultralytics 8.4.182): - The notebook JSON parses and every code cell compiles.
- **Data conversion on real files:** it fetched 113 items by range reads (Harmony4D `test/16_mma5` + 20 VICOS annotations per split) in 14 s. 85 were converted and 28 skipped (missing athlete). Labels drawn on the images line up on both datasets (checked by eye).
- Training (yolo11n-pose, 1 epoch, CPU), Ultralytics AP, the both-found metrics, the ONNX export and the wrapper all ran. The 1-epoch model is meaningless; this only checks the code path.
- **ONNX wrapper vs. Ultralytics** (COCO yolo11n-pose, 640 px, 23 test images): median keypoint difference **0.56 px**, same number of people on 21 of 23 images (off by one twice, near the score cutoff).
- **Not tested locally:** the GPU, the full 28k-image fetch, the 4 h training, and the RTMO comparison on Kaggle (`rtmlib` + `onnxruntime-gpu`). If the RTMO step fails, set `EVAL_RTMO = False`; the rest still runs.
